# Checklist for a rules file

The rules file (`CLAUDE.md` in a generated package) holds what is true in **every** session. Use this to check one, whether you are generating it or tightening it later.

## It must contain
- [ ] **A one-line statement of what the project is.**
- [ ] **What to read before starting any story**, in order: the plan, the last few log entries, the specific guide sections.
- [ ] **The log instruction and the exact entry format.**
- [ ] **The house rules** (files are the memory; decide before building; one story at a time; stop at the gates; ask before outward-facing or irreversible actions; report honestly; log every session; the owner owns the plan, and Claude changes it only after their yes; no secrets in chat; protect personal details; record gotchas).
- [ ] **The review gates**: where work stops and what Claude gives the owner at each stop.
- [ ] **Scope from the brief**: what is in, what is out (and "do not build it even if it seems helpful"), what is parked for later.
- [ ] **What must never happen**, copied from the brief in the user's own words.
- [ ] **How work is checked** for this kind of project (software, data and analysis, or documents and processes).
- [ ] **Where things live**: the list that grows as stories add things.
- [ ] **Gotchas learned so far**: starts empty, grows with a dated line each time something bites.
- [ ] **A short "Don't" list**: no out-of-scope work without a recorded decision; don't change the plan without the owner's yes; don't skip the log; don't call unchecked work done; don't ask for secrets in chat.
- [ ] **Who the owner is.**

## It must not contain
- [ ] Story-by-story detail (that belongs in the plan).
- [ ] History of what happened (that belongs in the log).
- [ ] Anything that is only true for part of the project; put it in the story or the guide it belongs to.
- [ ] A secret of any kind.
- [ ] Words the user would not understand without a definition.

## Keeping it good
- When a story adds something the next session needs to find, add a line to "Where things live".
- When something surprising bites, add a dated line to "Gotchas" the same day.
- When a rule turns out wrong, the owner changes it here and the log records why; never silently work around it.
- Keep it short enough that a session reads all of it every time. If it grows past a few pages, move detail into a guide and leave a pointer.
