# Plain-language glossary

Words the method uses, in the words to use when explaining them to someone who has never built anything. Explain a term the first time it comes up in a conversation; do not assume it is known.

| Term | Say it like this |
|---|---|
| **Project package** | The small set of plain text files that holds the whole project: the brief, the rules, the plan, the log and the guides. |
| **Brief** | The one-page record of what you told us the project is. Everything else is built from it. |
| **Rules file** | The page Claude reads at the start of every session so it follows the same rules each time. |
| **Plan** | The list of small steps (stories), in order, each with a ready-to-use instruction. |
| **Story** | One small piece of work that can be finished and checked in a single session. |
| **Prompt** | The instruction you give Claude to do a story. Each story has one ready to use. |
| **Log** | The running notes Claude adds to after every session, so no session starts from scratch. It is only ever added to. |
| **Review gate** | A planned pause. Claude stops, shows you what exists and how to look at it, and waits for your yes. |
| **Decision** | Something settled and written down, with a date, so it is not reopened by accident. |
| **Open question** | Something we do not know yet. Each one gets answered early, with evidence. |
| **Scope** | What the project does, and what it deliberately does not. |
| **Owner** | The person who makes every decision about the project. Claude suggests; the owner decides. |
| **Made-up data** | Believable pretend information used to build and judge a first version before anything real is connected. |
| **Sandbox / test copy** | A safe copy where changes cannot hurt anything real. Everything is tried here first. |
| **The safety check (doorway)** | One checked place in the project that every real change (an email, a payment, a deletion) must pass through, and that refuses anything not allowed. With clients, call it "one safety check that every message goes through", not "the doorway". |
| **Check / test** | Something that proves a piece of work does what it should. |
| **Break it on purpose** | After writing a check, deliberately break the thing it protects and make sure the check complains, then put it back. A check that can never fail proves nothing. |
| **Pinned sample** | A small real example with the right answer worked out by hand, kept so the work can always be checked against it. |
| **Independent source** | A second, separate way of getting the same fact, used to check the first. |
| **Needs extra care (⚠️)** | A warning on a story where a quiet mistake would be costly, so it gets extra care and checks. |
| **Snapshot (commit)** | A saved copy of the work at a moment in time, so it can be returned to. Done only when you ask, unless you chose otherwise. |
| **Feature map** | A list of what has been built so far, feature by feature: where each part lives, what it depends on, and which steps changed it. The log says how we got here; the map says what is here now. |
| **Step / story** | In conversation, "step"; in the plan, "story". The same thing: one small piece of work. |
| **Lite, Standard, Full** | How big the plan is (how many steps and checks it needs), not how much work it is for you. |
| **Fresh-eyes read** | Someone who was not involved reads it as the real audience would and says where they got lost. |
| **Plan updated** | A log entry Claude adds when it changes the plan, after you said yes to that exact change. |
| **Gotcha** | A surprising thing that went wrong once, written down so it does not go wrong twice. |
